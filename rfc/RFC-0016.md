# 1. Abstract（摘要）

Story Outline 是作者的故事设计文档——大纲、结构节拍、角色弧线。它不参与 Compiler 的一致性检查，是**设计层**的记录，服务于作者规划和 AI 上下文。

```text
   outline.toml（故事设计）
         ↓ 关联
   structure.toml（文本结构）     → 实际写了什么
   threads.toml（叙事线索）        → 怎么讲
```

Outline 回答"作者打算写什么"，structure 回答"实际写了什么"，threads 回答"怎么讲"。

------

# 2. Motivation

长篇小说需要全局规划。作者在动笔前（或写作过程中）需要记录：

- 这本书的**一句话内核**（premise）
- **三幕结构**（或五幕）的节拍点
- 每个角色的**成长弧线**
- 主线与支线的**纲领**

这些是设计意图，不是可验证的事实——Outline 不参与 Compiler 检查（没有 Error/Warning），但它是 AI 生成的关键上下文，也是作者自我对齐的工具。

> **Outline 不进 Compiler。** 它是设计文档，不是约束。作者可以偏离大纲——大纲只是起点。

------

# 3. File Format

```toml
# outline.toml — 项目根目录

[story]
title = "雨夜行"
genre = "武侠悬疑"
premise = "一个失去记忆的剑客在江南小镇寻找过去，卷入二十年阴谋"
theme = "身份认同与救赎"

# 角色弧线
[[arcs]]
character = "c_001"
name = "林风：从迷茫到觉醒"
stages = "迷茫 → 怀疑 → 发现 → 抉择 → 觉醒"
summary = "林风从不知自己是谁，到接受皇子身份，最终选择放下复仇"

[[arcs]]
character = "c_002"
name = "周明：忠诚的代价"
stages = "信任 → 动摇 → 背叛 → 救赎"
summary = "周明在职责与友情间挣扎"

# 关联叙事线索（RFC-0017）
[[storylines]]
thread = "t_001"
name = "主线：身份之谜"
summary = "贯穿全书的核心悬念"

[[storylines]]
thread = "t_005"
name = "支线：青衣门内鬼"
summary = "悬疑支线，第二幕展开"
```

# 4. Core Concepts

## 4.1 Story Meta

全局元信息：

| 字段 | 说明 |
|:--|:--|
| `title` | 书名 |
| `genre` | 类型（自由文本） |
| `premise` | 一句话内核（这本书讲什么） |
| `theme` | 主题（这本书探讨什么） |

## 4.2 Volumes（卷）

| 字段 | 说明 |
|:--|:--|
| `name` | 节拍名（如"第一幕：建置"） |
| `summary` | 本节拍的剧情摘要 |
| `thmes` | 本卷主题 |

Acts 按 TOML 数组顺序排列，顺序即叙事顺序。

## 4.3 Arcs（角色弧线）

| 字段 | 说明 |
|:--|:--|
| `character` | 角色的 StableId |
| `name` | 弧线名称 |
| `stages` | 成长阶段（自由文本） |
| `summary` | 弧线摘要 |

## 4.4 Storylines（主线/支线）

关联 Narrative Thread（RFC-0017）：

| 字段 | 说明 |
|:--|:--|
| `thread` | Thread 的 StableId |
| `name` | 线名称（如"主线""支线"） |
| `summary` | 线摘要 |

------

# 5. Source of Truth Model

Outline 是 **Source of Truth**（进 Git），但它**不约束**其他数据：

- Outline 记录设计意图
- Structure / Threads 记录实际实现
- 二者可以不一致（作者偏离大纲是常态）

> Outline 与 Structure 的偏差不产 Warning——偏离大纲是创作自由，不是错误。AI 上下文构建时会同时提供 Outline（意图）和 Structure（现状），让 AI 理解"作者想写什么"与"已经写了什么"的差距。

------

# 6. Compiler Rules

> **Outline 不参与 Compiler 检查。**

它是设计文档，不是约束。没有规则扫描 outline.toml 产出 Diagnostics。

唯一的例外是**引用完整性**——如果 Outline 的 `end_scene` 或 `character` 引用了不存在的 ID，Parser 产 Warning（"大纲引用了不存在的场景/角色"）。这是结构校验，不是叙事校验。

------

# 7. AI Context

AI Runtime 构建上下文时，Outline 提供全局意图：

```text
=== 故事大纲 ===
书名：雨夜行
内核：一个失去记忆的剑客在江南小镇寻找过去，卷入二十年阴谋
主题：身份认同与救赎

当前节拍：第二幕上（对抗）
节拍摘要：发现阴谋的冰山一角，被追杀，结识盟友

角色弧线：
- 林风：迷茫 → 怀疑 → [发现] → 抉择 → 觉醒（当前在"发现"阶段）
- 周明：信任 → [动摇] → 背叛 → 救赎（当前在"动摇"阶段）
```

AI 上下文使用人类可读的 summary，不用 StableId。

# 9. Open Questions

1. **Outline 版本**——作者改大纲后，是否保留历史版本？v0.1 不保留（Git 已追踪历史）。
2. **多大纲方案**——作者想尝试不同结构方案（A/B test）。是否支持多个 outline 文件？v0.1 不支持。
3. **节拍与场景的自动对齐**——能否自动检测"实际写的场景顺序是否符合大纲的节拍顺序"？属 Info 级提示，v0.2+。

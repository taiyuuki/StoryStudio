# 1. Abstract（摘要）

Timeline 是 Story Studio 的**时序坐标系**。它为 Knowledge Base 的 Assertion valid 窗口、Semantic Edge 的时序关系、Compiler 的时序规则提供统一的时间度量。

```text
   Assertion.valid { from, until }
   SemanticEdge.valid { from, until }
   Fragment 的叙事时间
                │
                ▼
         StoryTime（统一坐标）
                │
                ▼
         Compiler 时序规则（dead_revived, age_inconsistency...）
```

没有 Timeline，"角色 1086 年 17 岁"只是一个没有坐标的数字；有了 Timeline，Compiler 才能判断"1086 年到 1088 年之间角色年龄应该是 17→19"。

------

# 2. Design Principle（设计原则）

## 2.1 小说时间 vs 现实时间

小说的时间体系与现实不同：

- **现实时间**是线性的、均匀的、单向流动的。
- **小说时间**可能非线性（倒叙、插叙、平行叙事）、可能跳跃（"三年后"）、可能有多个时间线（主线 / 回忆 / 梦境）。

Timeline 必须表达**故事内的时间逻辑**，而非物理时间。

## 2.2 时间的三种粒度

| 粒度 | 表达 | 适用场景 |
|:--|:--|:--|
| **绝对纪年** | `year-1086`, `month-1086-03` | 历史小说、有明确年代设定的世界 |
| **叙事坐标** | `scene:sc_01_02` | 以场景为时间锚点（不知道具体年份，但知道先后） |
| **相对时间** | `+3y`（三年后） | 相对于某个基准点的偏移 |

v0.1 支持**绝对纪年 + 叙事坐标**，相对时间留待 v0.2。

## 2.3 核心挑战：叙事顺序 ≠ 时间顺序

```text
   叙事顺序（Document Graph）：    ch_01 → ch_02 → ch_03（回忆）→ ch_04
   时间顺序（Timeline）：          t_1086 → t_1088 → t_1080(回忆) → t_1090
```

Chapter 3 在叙事上是第 3 章，但在故事时间线上可能早于 Chapter 1（倒叙）。Timeline 必须独立于 Document Graph 维护时间顺序。

# 3. StoryTime（故事时间）

## 3.1 统一时间类型

```rust
/// 故事时间的统一表示
pub struct StoryTime {
    /// 时间坐标
    pub coord: TimeCoord,
    /// 精度（决定比较时的粒度）
    pub precision: TimePrecision,
}

pub enum TimeCoord {
    /// 绝对纪年：故事内历法的某年某月
    Absolute(StoryCalendar),
    /// 叙事坐标：绑定到某个 Scene / Fragment
    Narrative(StableId),
    /// 故事开始前（用于背景设定）
    BeforeStory,
    /// 故事结束后（用于尾声 / 后日谈）
    AfterStory,
    /// 未知（无法确定时间）
    Unknown,
}

pub struct StoryCalendar {
    pub year: i32,
    pub month: Option<u8>,    // 1-12，None 表示只精确到年
    pub day: Option<u8>,
}

pub enum TimePrecision {
    Year,
    Month,
    Day,
    Scene,       // 精确到场景
    Fragment,    // 精确到 Fragment
    Unspecified, // 未标注时间
}
```

## 3.2 时间比较

Timeline 的核心能力是**比较两个 StoryTime 的先后**。这是 Compiler 时序规则的基础。

```rust
impl StoryTime {
    /// 判断 self 是否在 other 之前
    pub fn is_before(&self, other: &StoryTime) -> bool {
        self.to_ordinal() < other.to_ordinal()
    }

    /// 转为可比较的序数
    /// 绝对纪年 > 叙事坐标（按 Document Graph 顺序）
    fn to_ordinal(&self) -> TimeOrdinal {
        match &self.coord {
            TimeCoord::Absolute(cal) => TimeOrdinal::Absolute(cal.year * 12 + cal.month.unwrap_or(1) as i32),
            TimeCoord::Narrative(id) => TimeOrdinal::Narrative(scene_order_of(id)),
            TimeCoord::BeforeStory => TimeOrdinal::BeforeStory,
            TimeCoord::AfterStory => TimeOrdinal::AfterStory,
            TimeCoord::Unknown => TimeOrdinal::Unknown,
        }
    }
}
```

> **混合坐标的比较**：绝对纪年与叙事坐标混用时，无法直接比较（"1086 年" vs "场景 sc_01_02"）。v0.1 的策略是：若 Scene 标注了 `story_time`（§4），则用标注值比较；否则按叙事顺序。混用且无标注时，Compiler 产出 Warning（"时间坐标不一致，无法比较"）。

# 4. Scene Timeline（场景时间标注）

## 4.1 Scene 的 story_time 字段

Scene 在 structure.toml 中可选标注故事时间：

```toml
# structure.toml

[scene.sc_01_02]
title = "河岸"
pov = "c_8A91D4"
fragments = ["f_0003", "f_0004", "f_0005"]
story_time = { year = 1086, month = 3 }   # 此场景发生在 1086 年 3 月
```

未标注 `story_time` 的 Scene，其时间默认为"叙事顺序"（按 Document Graph 中的位置）。

## 4.2 时间继承

Fragment 继承其所属 Scene 的 story_time：

```text
Scene sc_01_02 { story_time: 1086-03 }
  ├─ Fragment f_0003 → 时间 = 1086-03
  ├─ Fragment f_0004 → 时间 = 1086-03
  └─ Fragment f_0005 → 时间 = 1086-03
```

Fragment 级别不单独标注时间（v0.1）。一个场景内的所有 Fragment 共享同一时间点。

## 4.3 Chapter 级时间跨度

Chapter 可标注时间跨度，其下的 Scene 在此跨度内：

```toml
[chapter.ch_01]
title = "雨夜"
story_time_span = { from = { year = 1086, month = 3 }, until = { year = 1086, month = 4 } }
scenes = ["sc_01_01", "sc_01_02"]
```

Scene 的 story_time 必须落在 Chapter 的 time_span 内，否则 Compiler 产出 Warning。

# 5. Timeline Graph（时间线图）

## 5.1 构建

Compiler 维护一张 Timeline Graph，将所有时间标注组织为有序序列：

```text
Timeline Graph（按时间排序）：

  t_1080 ─── ch_03（回忆，倒叙）
     │
  t_1086-03 ── sc_01_02
     │
  t_1086-04 ── sc_01_03
     │
  t_1088 ─── ch_02
     │
  t_1090 ─── ch_04
```

- 每个 Scene 是 Timeline 上的一个点（或区间）。
- 倒叙的 Scene 按其 story_time 插入正确位置，而非叙事顺序位置。

## 5.2 时间查询

```rust
/// 查询某 Scene 在时间线上的位置
pub fn scene_time(scene_id: StableId, ir: &StoryIR) -> StoryTime {
    let scene = ir.document.get_scene(scene_id);
    if let Some(t) = &scene.story_time {
        StoryTime::from(t)
    } else {
        // 未标注 → 用叙事顺序
        StoryTime::narrative(scene_id)
    }
}

/// 查询某时间点处于哪些 Scene
pub fn scenes_at(time: StoryTime, ir: &StoryIR) -> Vec<StableId> {
    ir.document.all_scenes()
        .filter(|sc| scene_time(*sc, ir).contains(&time))
        .collect()
}
```

# 6. ValidityWindow（有效区间）

## 6.1 与 Assertion / Edge 的关系

Assertion 和带时序的 SemanticEdge 都使用 ValidityWindow（RFC-0002 §7.2、RFC-0015 §4）。Timeline 为 ValidityWindow 提供坐标语义。

```rust
pub struct ValidityWindow {
    pub from: Option<StoryTime>,
    pub until: Option<StoryTime>,
}

impl ValidityWindow {
    /// 判断某时间点是否在此窗口内
    pub fn contains(&self, time: &StoryTime) -> bool {
        let after_from = self.from.as_ref().map_or(true, |f| !time.is_before(f));
        let before_until = self.until.as_ref().map_or(true, |u| time.is_before(u));
        after_from && before_until
    }

    /// 判断两个窗口是否重叠
    pub fn overlaps(&self, other: &ValidityWindow) -> bool {
        // 标准区间重叠判断
        // ...
    }
}
```

## 6.2 开放区间

- `from = None` 表示"自故事开始"
- `until = None` 表示"直到故事结束 / 永久"
- 角色死亡后 `alive=false` 的 until 通常为 None（永久死亡）

# 7. Compiler Rules for Timeline（时序检查规则）

Timeline 为以下 Compiler 规则提供基础：

| 规则 ID | Phase | 检查内容 |
|:--|:--|:--|
| `validity_window_illegal` | Semantic | until 早于 from（区间倒置） |
| `assertion_contradiction` | Semantic | 两条同 subject+predicate 的 active Assertion，valid 重叠但 object 不同 |
| `dead_character_revived` | Semantic | alive=false 后，角色在更晚的时间点出场 |
| `age_inconsistency` | Semantic | 年龄未随时间正确增长（如 1086 年 17 岁，1085 年也 17 岁） |
| `scene_time_out_of_span` | Structure | Scene 的 story_time 超出 Chapter 的 time_span |
| `timeline_gap` | Style | 相邻 Scene 间有大段时间跳跃（如突然"十年后"）但无标注 |

## 7.1 年龄一致性检查示例

```rust
pub struct AgeInconsistency;

impl Rule for AgeInconsistency {
    fn id(&self) -> &str { "age_inconsistency" }
    fn phase(&self) -> RulePhase { RulePhase::Semantic }
    fn depends_on(&self) -> &[Dependency] {
        &[Dependency::Assertion, Dependency::Entity]
    }
    fn run(&self, ctx: &mut RuleContext) {
        let kb = match ctx.kb { Some(kb) => kb, None => return };

        // 按角色分组，获取所有年龄断言
        for (char_id, age_assertions) in kb.group_by_subject("age") {
            // 按 valid.from 排序
            let sorted = age_assertions.sorted_by(|a, b| {
                a.valid.from.cmp(&b.valid.from)
            });

            // 检查相邻断言的年龄差与时间差是否一致
            for window in sorted.windows(2) {
                let (earlier, later) = (&window[0], &window[1]);
                let years_passed = later.valid.from.year - earlier.valid.from.year;
                let age_diff = later.object - earlier.object;

                if age_diff != years_passed {
                    ctx.error(
                        "age_inconsistency",
                        format!("角色 {:?} 在 {} 年 {} 岁，{} 年 {} 岁，年龄差 {} 与时间差 {} 不符",
                            char_id, earlier_year, earlier_age,
                            later_year, later_age, age_diff, years_passed),
                        SourceLocation::assertion(later.id),
                    );
                }
            }
        }
    }
}
```

# 8. Special Timeline Patterns（特殊时间模式）

## 8.1 倒叙 / 插叙

```text
叙事顺序：  ch_01(1086) → ch_02(1088) → ch_03(回忆1080) → ch_04(1090)
时间顺序：  ch_03(1080) → ch_01(1086) → ch_02(1088) → ch_04(1090)
```

- 回忆章节标注较低的 story_time。
- Compiler 不会因为"ch_03 出现在 ch_02 之后"而认为时间倒流——它按 story_time 比较。
- `dead_character_revived` 检查的是**时间顺序**而非叙事顺序：角色在 1090 年死亡，回忆 1080 年的出场不算"复活"。

## 8.2 平行叙事

两条同时进行的故事线（A 线和 B 线），它们的 Scene 标注相同或重叠的 story_time。Compiler 接受同一时间点的多个 Scene（不视为错误）。

## 8.3 时间跳跃

"三年后"的场景：

```toml
[chapter.ch_02]
title = "三年后"
story_time_span = { from = { year = 1089 }, until = { year = 1089 } }
```

Compiler 的 `timeline_gap` 规则（Style Phase）可提示作者"此处有时间跳跃"，但不视为错误。

# 9. Serialization（序列化）

Timeline 数据分散存储，无独立文件：

| 数据 | 存储位置 |
|:--|:--|
| Scene 的 story_time | structure.toml 的 `[scene.xxx]` |
| Chapter 的 time_span | structure.toml 的 `[chapter.xxx]` |
| Assertion 的 valid | knowledge/assertions.toml |
| Edge 的 valid | Semantic Graph（派生自 Assertion） |

Timeline Graph 本身是**派生结构**，由 Compiler 从上述数据构建，不持久化。

# 11. Open Questions

1. **多历法系统**：奇幻小说可能有多种历法（如"创世纪 1086 年" vs "旧历 2086 年"）。是否需要历法转换？（倾向：v0.1 单一历法，多历法留待 v0.2。）
2. **模糊时间**："某年春天""不久之后"如何表达？（倾向：v0.1 用 Unspecified 精度，不强制精确。）
3. **时间线可视化**：Timeline Graph 是否需要独立的可视化视图（类似 Timeline View）？（倾向：是，但属于 Editor 功能，非本 RFC 范围。）
4. **梦境 / 幻觉的时间归属**：梦境中的事件，其 story_time 是真实时间还是梦境内时间？（倾向：v0.1 归为真实时间 + status:dreaming 断言标注。）

------

# Appendix

> **Timeline 是时序检查的坐标系。它让"角色 1086 年 17 岁"从一个无坐标的数字变成可比较、可验证的时间事实。叙事顺序不等于时间顺序——倒叙的回忆不是复活。**

# 1. Abstract（摘要）

Graph 是 Story Studio 的**只读可视化层**：将 Story IR 中的实体关系、时间线、出场分布等以图形方式呈现，帮助作者鸟瞰全局结构。

```text
   Story IR（只读）
         │
         ▼
    Graph Views（多种视图）
    ├─ 关系图（角色 / 道具 / 地点的关联）
    ├─ 时间线视图（事件先后）
    ├─ 出场分布（角色出场密度）
    └─ 叙事结构（章节节奏）
         │
         ▼
    Editor 渲染（交互式）
```

> **Graph 是纯展示层。** 它只读 IR，不产出 Change，不修改任何数据。它是作者理解全局的工具，不是编辑工具。

------

# 2. Design Principle（设计原则）

## 2.1 派生数据，不持久化

Graph 的所有视图数据都是从 IR + KB + Location Index **派生**的：

- 关系图 ← Semantic Graph 的节点与边
- 时间线 ← Timeline Graph（RFC-0009）
- 出场分布 ← Location Index

这些视图**不持久化**——每次打开时从当前 IR 重新计算。符合 RFC-0001 §9.4 的派生缓存原则。

## 2.2 与 Editor 解耦

Graph 是 Editor 的一个功能模块，但它的数据来源（IR）与编辑操作（Change）完全解耦：

- Graph 展示的是 IR 的**快照**
- 作者在 Editor 中的编辑经 Parser → Compiler 后更新 IR，Graph 自动刷新
- Graph 本身不触发编辑

## 2.3 交互式但不修改

Graph 可交互（点击节点跳转、缩放、过滤），但交互只产生**导航行为**（跳转到某 Fragment），不产生 Change。

------

# 3. Graph Views（视图类型）

## 3.1 Relationship Graph（关系图）

展示 Semantic Graph 的实体与关系：

```text
                    ┌──────────┐
          knows     │  林风     │  knows
    ┌───────────────┤  (hero)  ├───────────────┐
    │               └────┬─────┘               │
    │                    │ holds                │
    ▼                    ▼                      ▼
 ┌──────┐          ┌──────────┐          ┌──────┐
 │ 周明 │          │ 寒霜剑   │          │ 林雨 │
 │(zhou)│          │(frost)   │          │(rain)│
 └──────┘          └──────────┘          └──────┘
```

- 节点 = Semantic Entity（Character / Item / Location / Organization）
- 边 = SemanticEdge（knows / holds / located_at / member_of）
- 边可按时序过滤（"只看 1086 年的关系"）

## 3.2 Timeline View（时间线视图）

按时间顺序展示事件：

```text
  1080 ─── ● 林风出生
              │
  1086 ─── ● 林风获得寒霜剑（sc_01_02）
              │
  1088 ─── ● 林风加入青云门（sc_03_01）
              │
  1090 ─── ● 林风 vs 周明（sc_05_02）
              │
  1092 ─── ✕ 林风死亡（sc_08_01）
```

- 数据来源：Timeline Graph（RFC-0009 §5）+ KB Assertions
- 倒叙的 Scene 按其 story_time 插入正确位置
- 死亡事件用特殊标记（✕）

## 3.3 Appearance Heatmap（出场热度图）

展示角色在各章节的出场密度：

```text
           ch_01  ch_02  ch_03  ch_04  ch_05  ...
  林风     █████ █████ █████ ████░ █████ █████
  周明     ░░░░░ ████░ ░░░░░ █████ █████ ░░░░░
  林雨     ██░░░ ░░░░░ █████ ░░░░░ ████░ █████
```

- 数据来源：Location Index（每个角色的出场 Fragment 分布）
- 帮助发现"角色消失了几章"或"某角色戏份过重"

## 3.4 Narrative Structure（叙事结构）

展示章节的叙事功能分布：

```text
  ch_01 [exposition] ── ch_02 [rising] ── ch_03 [flashback]
       ── ch_04 [rising] ── ch_05 [climax] ── ch_06 [resolution]
```

- 数据来源：Scene 的 `function` 字段（RFC-0007 §5）
- 帮助作者审视叙事节奏（"高潮太早""伏笔集中"）

# 4. Graph Data Model（图数据模型）

Graph 视图的统一数据表示：

```rust
/// 一个图视图的渲染数据（派生自 IR）
pub struct GraphView {
    pub kind: ViewKind,
    pub nodes: Vec<GraphNode>,
    pub edges: Vec<GraphEdge>,
    pub layout: LayoutHint,
}

pub enum ViewKind {
    Relationship,
    Timeline,
    AppearanceHeatmap,
    NarrativeStructure,
}

pub struct GraphNode {
    pub id: StableId,           // 引用 IR 实体
    pub label: String,          // Display Name
    pub node_type: GraphNodeType,
    pub metadata: BTreeMap<String, String>,  // 额外信息（如出场次数）
}

pub enum GraphNodeType {
    Character,
    Item,
    Location,
    Organization,
    Event,
    Scene,
    Chapter,
}

pub struct GraphEdge {
    pub from: StableId,
    pub to: StableId,
    pub label: String,          // 关系描述（如 "knows"、"holds"）
    pub valid: Option<ValidityWindow>,  // 时序关系
}

pub enum LayoutHint {
    Force,        // 力导向布局（关系图）
    Timeline,     // 时间轴布局
    Grid,         // 网格布局（热度图）
    Linear,       // 线性布局（叙事结构）
}
```

## 4.1 派生构建

```rust
/// 从 IR 派生关系图视图
pub fn build_relationship_graph(
    ir: &StoryIR,
    filter: &GraphFilter,
) -> GraphView {
    let mut nodes = Vec::new();
    let mut edges = Vec::new();

    // 收集节点
    for entity in ir.semantic.all_entities() {
        if filter.includes(entity) {
            nodes.push(GraphNode {
                id: entity.id,
                label: entity.display_name.clone(),
                node_type: entity.into(),
                metadata: BTreeMap::new(),
            });
        }
    }

    // 收集边
    for edge in ir.semantic.all_edges() {
        if filter.includes_edge(edge) {
            edges.push(GraphEdge {
                from: edge.from,
                to: edge.to,
                label: edge.relation.to_string(),
                valid: edge.valid.clone(),
            });
        }
    }

    GraphView {
        kind: ViewKind::Relationship,
        nodes,
        edges,
        layout: LayoutHint::Force,
    }
}
```

# 5. Interaction（交互）

## 5.1 导航

点击 Graph 节点 → 跳转到相关位置：

| 点击对象 | 跳转目标 |
|:--|:--|
| Character 节点 | 该角色的 Entity 文件 |
| Item 节点 | 该道具的 Entity 文件 |
| Scene 节点（时间线） | 该 Scene 的第一个 Fragment |
| 事件标记（时间线） | 支撑该事件的 Fragment |

> 导航只触发 Editor 的跳转，不产生 Change。

## 5.2 过滤

Graph 支持过滤器：

- **按实体类型**：只看 Character / 只看 Item
- **按时序**：只看某时间段的关系
- **按关系类型**：只看 holds / 只看 knows
- **按章节范围**：只看 ch_01–ch_05 的关系

## 5.3 自动刷新

Graph 订阅 IR 的变更事件。作者保存后（Parser → Compiler 更新 IR），Graph 自动重新计算并刷新。

```rust
impl GraphPanel {
    fn on_ir_updated(&mut self, new_ir: &StoryIR) {
        self.view = build_relationship_graph(new_ir, &self.filter);
        self.render();
    }
}
```

# 6. Performance（性能）

百万字小说的图规模：

| 数据 | 规模 |
|:--|:--|
| Semantic 节点 | ~300 |
| Semantic 边 | ~500–1000 |
| 出场记录（Location Index） | ~2000 Fragment × 平均 3 实体 = ~6000 |

- 关系图的节点 / 边数量在数百级，力导向布局可接受。
- 出场热度图是矩阵渲染（章节 × 角色），O(章节 × 角色) 计算量小。
- 派生计算是 O(n) 遍历，毫秒级。

> Graph 不需要增量更新——每次 IR 变更后全量重算视图，性能足够。

# 8. Open Questions

1. **图布局算法**：力导向布局在节点较多时可能不稳定。是否需要固定布局（作者手动拖拽后保存位置）？（倾向：v0.1 自动布局，手动保存留 v0.2。位置存 `.novelstudio/`。）
2. **Graph 的序列化**：是否支持将图导出为图片 / SVG？（倾向：是，作为 Exporter 的特殊格式。）
3. **实时协作**：多人查看同一 Graph 时如何同步？（v0.1 单作者，不涉及。）
4. **Graph 上的编辑**：是否允许在关系图上直接拖拽创建关系？（倾向：v0.2+，需生成 Change 走 Dry-Run。）

# Appendix

> **Graph 是 IR 的镜子。它只读、只展示、只导航。关系图看全局，时间线看先后，热度图看分布，叙事结构看节奏——四个视角，同一份 IR，零修改。**

# 1. Abstract（摘要）

Export 是 Story Studio 数据流的终端：将已验证的 Story IR 转换为可发布的成品格式（EPUB / PDF / Markdown / HTML）。

```text
   Story IR（已验证）
         │
         ▼
    Export Pipeline
    ├─ 格式选择（EPUB / PDF / MD / HTML）
    ├─ 渲染计算（章节编号、目录、分页）
    ├─ Fragment 拼接（按链表顺序无缝合并）
    └─ 锚点过滤（剥离 <!-- @ --> 注释）
         │
         ▼
    成品文件
```

> **Export 只读 IR，不修改 IR。** 它所需的所有渲染信息在管道内计算，不写回 IR（RFC-0001 §7 第 7 条）。

------

# 2. Design Principle（设计原则）

## 2.1 只读契约

Export 是 IR 的**纯消费者**：

- 读取 Document Graph 获取章节结构与 Fragment 正文
- 读取 Semantic Graph 获取元信息（可选，如角色表附录）
- **不修改任何 IR 节点**
- **不在 IR 中预留渲染字段**（章节编号、页码等都是导出时计算）

## 2.2 渲染信息不进 IR

| 渲染信息 | 计算时机 | 存储位置 |
|:--|:--|:--|
| 章节编号（第 1 章、第 2 章） | Export 时遍历 Document Graph | 不存储（即时计算） |
| 页码 | 排版引擎计算 | 不存储 |
| 目录层级 | Export 时递归构建 | 不存储 |
| Fragment 拼接顺序 | 按链表 / structure.toml 数组 | 不存储（即时拼接） |

> 若需缓存渲染中间结果（如 Render Context），存于 `.novelstudio/cache/`，不进 Git（RFC-0001 §7 第 7 条）。

## 2.3 格式无关的 IR

Story IR 的 Core Schema 不为任何特定导出格式预留字段。同一个 IR 可以导出为 EPUB、PDF、Markdown，IR 本身不关心导出目标。

# 3. Export Pipeline（导出管线）

## 3.1 通用流程

```rust
pub trait Exporter {
    /// 导出格式标识
    fn format(&self) -> ExportFormat;

    /// 执行导出
    fn export(&self, ir: &StoryIR, options: &ExportOptions) -> Result<ExportOutput, ExportError>;
}

pub enum ExportFormat {
    Epub,
    Pdf,
    Markdown,
    Html,
    Custom(String),
}

pub struct ExportOptions {
    /// 导出范围（全部 / 指定章节）
    pub scope: ExportScope,
    /// 是否包含附录（角色表、地点表、道具表）
    pub include_appendix: bool,
    /// 锚点处理方式
    pub anchor_handling: AnchorHandling,
    /// 格式专属参数
    pub format_params: BTreeMap<String, String>,
}

pub enum ExportScope {
    All,
    Chapters(Vec<StableId>),
}

pub enum AnchorHandling {
    /// 剥离所有 <!-- @ --> 注释（成品不含内部标记）
    Strip,
    /// 保留为 HTML 注释（调试用）
    Keep,
}
```

## 3.2 管线阶段

```rust
pub fn run_export(
    exporter: &dyn Exporter,
    ir: &StoryIR,
    options: &ExportOptions,
) -> Result<ExportOutput, ExportError> {
    // 1. 前置检查：是否有 Error 级诊断
    if has_blocking_errors(ir) {
        return Err(ExportError::HasErrors);
    }

    // 2. 遍历 Document Graph，按链表顺序收集 Fragment
    let manuscript = collect_manuscript(ir, &options.scope);

    // 3. 计算渲染信息（章节编号、目录）
    let render_ctx = build_render_context(&manuscript);

    // 4. 锚点处理
    let cleaned = process_anchors(manuscript, &options.anchor_handling);

    // 5. 格式化输出
    let output = exporter.export(&cleaned, &render_ctx, options)?;

    Ok(output)
}
```

# 4. Manuscript Assembly（正文拼接）

## 4.1 Fragment 无缝拼接

Export 按 Document Graph 的链表顺序遍历 Fragment，将正文无缝拼接：

```rust
fn collect_manuscript(ir: &StoryIR, scope: &ExportScope) -> Manuscript {
    let mut chapters = Vec::new();

    for chapter_id in ir.document.chapters_in_order() {
        if !scope.includes(chapter_id) { continue; }

        let mut scenes = Vec::new();
        for scene_id in ir.document.scenes_of(chapter_id) {
            let mut fragments = Vec::new();
            for frag_id in ir.document.fragments_of(scene_id) {
                let frag = ir.document.get_fragment(frag_id);
                fragments.push(frag.text.clone());
            }
            // 同一 Scene 内的 Fragment 无缝拼接（不加分隔）
            scenes.push(SceneText {
                title: ir.document.get_scene(scene_id).title.clone(),
                body: fragments.join("\n\n"),
            });
        }
        chapters.push(ChapterText {
            title: ir.document.get_chapter(chapter_id).title.clone(),
            scenes,
        });
    }

    Manuscript { chapters }
}
```

> **Fragment 边界不产生视觉分隔。** 拼接时用段落换行（`\n\n`），Fragment 之间的边界对读者不可见。Scene 标题可选展示，Chapter 标题必须展示。

## 4.2 章节编号

```rust
fn build_render_context(manuscript: &Manuscript) -> RenderContext {
    RenderContext {
        chapter_numbers: manuscript.chapters.iter().enumerate()
            .map(|(i, ch)| (ch.id, ChapterNumber::new(i + 1)))
            .collect(),
        // 总字数、目录树等
        total_words: count_words(manuscript),
        toc: build_toc(manuscript),
    }
}
```

- 章节编号从 1 开始，按 Document Graph 顺序。
- 编号是导出时计算，不读 IR 的任何字段。

# 5. Anchor Handling（锚点处理）

## 5.1 剥离内部标记

Fragment 正文中的锚点注释（`<!-- @entity ... -->`）是内部标记，导出时必须剥离：

```rust
fn process_anchors(manuscript: Manuscript, mode: &AnchorHandling) -> Manuscript {
    match mode {
        AnchorHandling::Strip => {
            // 移除所有 <!-- @... --> 注释
            manuscript.map_text(|t| strip_anchor_comments(t))
        }
        AnchorHandling::Keep => manuscript,  // 保留（调试用）
    }
}
```

```text
输入（Fragment 正文）：
  <!-- @entity hero: appears -->
  林风推开门，雨水顺着发梢滴落。

剥离后：
  林风推开门，雨水顺着发梢滴落。
```

## 5.2 frontmatter 剥离

Fragment 的 YAML frontmatter 也在导出时剥离——成品只含正文。

# 6. Pre-export Validation（导出前校验）

## 6.1 Error 阻断

```rust
fn has_blocking_errors(ir: &StoryIR) -> bool {
    // 检查最近一次编译的诊断
    // 有 Error 级诊断 → 阻断导出
    ir.last_diagnostics()
        .iter()
        .any(|d| d.severity == Severity::Error)
}
```

- **有 Error 则不导出**——避免导出一个有结构问题的成品。
- 可通过配置覆盖（`allow_export_with_errors: true`），但默认阻断。
- Warning 不阻断导出（但可在成品附录中列出）。

## 6.2 完整性检查

| 检查 | 级别 | 说明 |
|:--|:--|:--|
| 有 Error 级诊断 | 阻断 | 默认不导出有问题的成品 |
| 有孤儿 Fragment | Warning | 未被 structure.toml 引用的 Fragment 不含在导出中 |
| 有 Stale 诊断 | Info | 提示"部分诊断可能过期，建议先全量编译" |

# 7. Appendix Generation（附录生成）

## 7.1 可选附录

导出时可选择包含附录：

| 附录 | 内容 | 来源 |
|:--|:--|:--|
| 角色表 | 所有 Character 的 display_name + 简介 | Semantic Graph |
| 地点表 | Location 层级树 | Semantic Graph |
| 道具表 | Item 列表 + 持有者 | Semantic Graph + KB |
| 时间线 | 按时间顺序的事件列表 | Timeline Graph |

## 7.2 附录的确定性

附录内容从 IR + KB 派生，是确定性的。同一 IR 导出两次，附录内容一致。

# 8. Format-specific Exporters（各格式导出器）

## 8.1 Markdown Exporter

最简单的导出器——IR 本身就是 Markdown 拼接：

```rust
pub struct MarkdownExporter;

impl Exporter for MarkdownExporter {
    fn format(&self) -> ExportFormat { ExportFormat::Markdown }

    fn export(&self, ir: &StoryIR, options: &ExportOptions) -> Result<ExportOutput, ExportError> {
        let manuscript = collect_manuscript(ir, &options.scope);
        let cleaned = process_anchors(manuscript, &options.anchor_handling);
        let ctx = build_render_context(&cleaned);

        let mut md = String::new();
        md.push_str(&format!("# {}\n\n", cleaned.title));

        for (i, chapter) in cleaned.chapters.iter().enumerate() {
            md.push_str(&format!("## 第{}章 {}\n\n", i + 1, chapter.title));
            for scene in &chapter.scenes {
                if let Some(t) = &scene.title {
                    md.push_str(&format!("### {}\n\n", t));
                }
                md.push_str(&scene.body);
                md.push_str("\n\n");
            }
        }

        if options.include_appendix {
            md.push_str(&generate_appendix_markdown(ir));
        }

        Ok(ExportOutput::file(md, "manuscript.md"))
    }
}
```

## 8.2 EPUB Exporter

- 使用 EPUB 生成库（如 Rust 的 `epub-builder`）。
- 每章一个 XHTML 文件。
- 内嵌目录（NCX）。
- 元信息（书名、作者）从 `project.toml` 读取。

## 8.3 PDF Exporter

- 通过 Markdown → HTML → PDF 管线（或 LaTeX）。
- 支持中文字体。
- 分页由排版引擎计算。
- v0.1 可先输出 HTML，PDF 留 v0.2（依赖较重）。

# 10. Open Questions

1. **PDF 方案**：用 Markdown→HTML→PDF（简单但排版弱）还是 LaTeX（排版强但依赖重）还是 Typst（现代但生态新）？（倾向：v0.1 先 HTML，PDF 方案待评估 Typst。）
2. **导出模板**：是否支持自定义导出模板（CSS / LaTeX 模板）？（倾向：是，模板存于 config/。）
3. **序列导出**：系列小说（多 Book）是否支持统一导出？（v0.1 单 Book，留扩展。）
4. **增量导出**：只导出变化的章节？（倾向：v0.1 全量导出，增量导出留 v0.2。）

# Appendix

> **Export 是 IR 的纯消费者。它只读不写，渲染信息在管道内计算不进 IR，锚点在导出时剥离。同一个 IR 可以导出为任何格式——格式无关是 IR 的核心承诺。**
